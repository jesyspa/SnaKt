Scene 1 — The Verification Lab
🧑‍💻
Dev
I want to formally verify that maxCharacter() is correct. Easy — I'll write a postcondition!
fun maxCharacter(s: String): Char {
    postconditions<Char> { m ->
        // "every character is ≤ m"
        forAll<Int> { (0 <= it && it < s.length) implies (s[it] <= m) }
    }
    // ... body ...
}
🧑‍💻
Dev
Wait. forAll only proves m is an upper bound. It doesn't prove m actually appears in the string!
The Gap in Logic
forAll says: "For every index i, s[i] ≤ m"

This proves m is an upper bound — but the maximum could be unreachable! A prover could satisfy this with m = '~' even if '~' never appears.
What We Need
exists would say: "There exists some index i where s[i] == m"

This is the witness — proof that m is actually attained, not just an upper bound floating in the air.

Scene 3 — formver.annotations / Builtins.kt
📜
Builtins
First stop: the public API. Users call exists { } in Kotlin source, so I need to declare it as a top-level function. At runtime it just throws — the verifier intercepts it before the JVM ever runs it.
Before (Builtins.kt)
fun <T> forAll(
    body: InvariantBuilder.(T) -> Unit
): Boolean = throw FormverFunctionCalledInRuntimeException("forAll")

// ← nothing here for exists
After — new declaration added
fun <T> forAll(
    body: InvariantBuilder.(T) -> Unit
): Boolean = throw FormverFunctionCalledInRuntimeException("forAll")

fun <T> exists(
    body: InvariantBuilder.(T) -> Unit
): Boolean = throw FormverFunctionCalledInRuntimeException("exists")
Why does it throw? These are specification-only functions. The Kotlin compiler sees them as normal functions, but the formver plugin intercepts every call site and rewrites it to Viper logic. If someone somehow called exists { } on the JVM directly, the throw gives a clear error instead of silent wrong behavior.

Scene 4 — The IR Node: ExistsEmbedding.kt (new file)
🧩
IR Node
I'm the compiler's internal representation of an exists expression. Think of me as a typed box that holds: the bound variable, the conditions, and optional trigger hints for the SMT solver.
ExistsEmbedding.kt — brand new file
data class ExistsEmbedding(
    val variable: VariableEmbedding,      // the bound variable  (e.g. "i")
    val conditions: List<ExpEmbedding>,   // the body predicates
    val triggerExpressions: List<ExpEmbedding> = emptyList(),  // SMT triggers
) : ExpEmbedding {

    override val type: TypeEmbedding
        get() = buildType { boolean() }   // always returns Boolean

    override fun children(): Sequence<ExpEmbedding> = conditions.asSequence()
    override fun <R> accept(v: ExpVisitor<R>): R = v.visitExistsEmbedding(this)
}
Mirror image of ForAllEmbedding
// ForAllEmbedding (existing)
data class ForAllEmbedding(
    val variable: VariableEmbedding,
    val conditions: List<ExpEmbedding>,
    val triggerExpressions: ...
) : ExpEmbedding
Intentionally identical shape Same fields, same visitor hook. The only difference lives downstream in the linearizer — Forall uses implication (Implies), while Exists uses conjunction (And).

Scene 5 — FullySpecialKotlinFunction.kt + StmtConversionContext.kt
🔌
Wiring
When the compiler sees a call to exists { ... }, two things happen:
① Recognition: the call site dispatcher matches it
② Conversion: a fresh anonymous variable is created and the body becomes conditions
① Recognition (FullySpecialKotlinFunction.kt)
addFunction(forAllCallableType,
    SpecialPackages.formver,
    name = "exists") { args, ctx ->

    val arg = args.first()
    val lambda = arg.ignoringMetaNodes()
        as? LambdaExp
    val param = lambda.function
        .valueParameters.first()
    val body = lambda.function.body
    ctx.insertExistsFunctionCall(
        param.symbol, body)
}
② Conversion (StmtConversionContext.kt)
fun StmtConversionContext.insertExistsFunctionCall(
    symbol: FirValueParameterSymbol,
    block: FirBlock,
): ExpEmbedding {
    val anonVar = freshAnonBuiltinVar(
        embedType(symbol.resolvedReturnType))

    return withNoScope {
        withMethodCtx(methodCtxFactory) {
            val (invariants, triggers) =
                collectInvariantsAndTriggers(block)
            ExistsEmbedding(
                anonVar, invariants, triggers)
        }
    }
}
freshAnonBuiltinVar — a fresh internal variable (e.g. anon_3) that becomes the existential witness variable in Viper. The lambda body's statements become the conditions list.

Scene 6 — Visitor Pattern: ExpVisitor, ExpPurityVisitor
🦋
Visitor
The IR uses the Visitor pattern — every expression node type gets a visit*() method. Adding a new node means updating every visitor that traverses the tree.
ExpVisitor interface
interface ExpVisitor<R> {
    // existing visitors ...
    fun visitForAllEmbedding(
        e: ForAllEmbedding): R = visitDefault(e)
    fun visitExistsEmbedding(
        e: ExistsEmbedding): R = visitDefault(e)
    fun visitPredicateAccessPermissions(...
    // ...
}
Default falls back to visitDefault — so visitors that don't care about exists still compile without change.
ExpPurityVisitor
class ExprPurityVisitor(...) {
    // ...
    override fun visitForAllEmbedding(
        e: ForAllEmbedding) =
        e.allChildrenPure(this)

    override fun visitExistsEmbedding(
        e: ExistsEmbedding) =
        e.allChildrenPure(this)
}
exists is a pure expression (no side effects) — it may appear in postconditions, loop invariants, and preconditions.

Scene 7 — LinearizationVisitor.kt: Lowering to Viper AST
⚗️
Linearizer
This is where the magic happens. I translate the IR node into Silver's Exp.Exists. The tricky part: what do we prepend to the body?
Three cases for the body expression
val charBound = e.variable.charDomainBoundOrNull()
Exp.Exists(
    variables = listOf(e.variable.toLocalVarDecl()),
    triggers  = viperTriggers,
    exp = when {
        // case 1: reference type → filter by runtime type tag
        e.variable.isOriginallyRef -> Exp.And(
            e.variable.toViperExp(ctx).isOf(e.variable.type.runtimeType),
            conjunction
        )
        // case 2: Char → add domain bound [0, 65536)
        charBound != null -> Exp.And(charBound, conjunction)
        // case 3: plain Int/Boolean → body as-is
        else -> conjunction
    }
)
vs. ForAll — key difference
// ForAll uses Implies:
Exp.Forall(
    exp = when {
        isRef  -> Exp.Implies(bound, body)
        isChar -> Exp.Implies(bound, body)
        else   -> body
    }
)

// Exists uses And:
Exp.Exists(
    exp = when {
        isRef  -> Exp.And(bound, body)
        isChar -> Exp.And(bound, body)
        else   -> body
    }
)
Why the difference?
∀x. P(x) → Q(x) — "for all x in range, if P then Q"

∃x. P(x) ∧ Q(x) — "there exists x where P AND Q"

Using And in exists means the witness must simultaneously satisfy both the domain bound AND the body condition.

Scene 8 — The Char Bound: a subtle Viper concern
🔢
Viper Int
In Viper, ALL quantifiers range over all integers — including negative ones! A Kotlin Char is only 0..65535.
🛡️
Guard
So we automatically inject 0 ≤ anon && anon < 65536 as a domain bound, keeping the quantifier inside the valid Unicode range.
Without the bound
// Silicon would try to prove:
exists anon: Int ::
    anon == 0

// Problem: this is trivially satisfiable —
// but forAll without the bound would
// range over negative Ints too!
// forAll c: Int :: 0 <= c
// would FAIL for c = -1
With the bound (actual output)
// ForAll emits Implies:
forall anon: Int ::
    0 <= anon && anon < 65536 -->
    body

// Exists emits And:
exists anon: Int ::
    0 <= anon && anon < 65536 &&
    body
Known limitation documented in tests: exists<Char> with a simple equality witness (like c == '') emits correct Viper but Silicon doesn't instantiate triggers automatically for it, so it reports a verification error. This is a known SMT trigger gap — a separate, deferred limitation — not a bug in the bound emission. The tests pin this behavior explicitly.

Scene 9 — The Payoff: maxCharacter fully verified!
🎉
Dev
With exists<T>, I can now write the complete, watertight specification!
exists.kt — the flagship test
fun maxCharacter(s: String): Char {
    preconditions { s.length > 0 }
    postconditions<Char> { m ->
        forAll<Int> { (0 <= it && it < s.length) implies (s[it] <= m) }  // m is an upper bound
        exists<Int> { 0 <= it && it < s.length && s[it] == m }              // m is attained ← NEW!
    }
    var m = s[0]; var i = 1
    while (i < s.length) {
        loopInvariants {
            1 <= i && i <= s.length
            forAll<Int> { (0 <= it && it < i) implies (s[it] <= m) }
            exists<Int> { 0 <= it && it < i && s[it] == m }  // carries the witness forward
        }
        if (s[i] > m) { m = s[i] }
        i += 1
    }
    return m
}
